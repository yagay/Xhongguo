# In-app PiP-style window

The existing in-app mini setting now uses a single observed TTVideoEngine and its existing renderer host. Bottom-tab and explicit same-app non-player Activity navigation may dock the host and attach its one overlay to the foreground Activity in the same task. A new player page, another verified playing engine, or owner destruction ends the mini session safely. No new decoder, external overlay permission, forced release suppression, or changes to authorization. Touch anywhere on the window to drag and snap; tap controls, double tap size, close pauses, expand returns via the original tab or REORDER_TO_FRONT. Controls hide after three seconds. Activity/window reattachment may recreate the rendering surface; real device testing is necessary. Same-Activity fragment routes not covered by the existing bottom-tab hook, cross-task and cross-app transitions, and destroyed owner are not guaranteed. The system-media feature remains independent.

Test: home→theater→mine→search/settings/detail→back, tap pause/play, drag/resize and close, expand to original, start another drama, series→non-player activity, lock/unlock with system media enabled, owner destruction. Verify one decoder, no wrong media, no foreground stealing, no black surface, and that explicit pause is respected.
