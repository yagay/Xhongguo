# Xhongguo 设置重构（2026-11-11）

## 统一分类与共享配置

模块 App 内的 `SettingsActivity` 和红果内的 Hook 弹出面板
均使用 `SettingsCatalog.kt` 的分类、标题、说明、默认值和键名。
不创建新的设置存储、不重新命名原有开关，也不丢失已经保存的配置。

首页仅显示「启用 Xhongguo」及五至六个分类入口：

- 播放与小窗：系统媒体、应用内小窗、画质、默认倍速与手势
- 界面与导航：隐藏控件、进度条、刷新与底部导航
- 我的页面：五个快捷入口和四个右侧菜单选项
- 内容与会员：广告、VIP 与图标
- 工具与高级：下载、OLED 与通知栏菜单
- 诊断与日志：导出诊断 ZIP（模块 App 提供；红果内不启动额外页面）

点击分类才展开其设置项。选择倍速/编辑下载限制保留原有独立小弹窗。
系统返回键在二级设置回到分类首页，首页返回则关闭。
模块 App 内的设置同样采用分组导航，Android 返回键可逐级返回。

## 长按视频：在同一红果 Activity 弹出设置

旧流程：
`视频长按 → Xhongguo.MainActivity → SettingsActivity`

现流程：
`视频长按 → 原生菜单关闭 → 当前红果 Activity 内 Dialog → 分类设置`

`Hooks.openLongPressModuleSettings()` 不再创建 `Intent`、
不加 `NEW_TASK`/ `CLEAR_TOP`，也不启动模块主页。

弹窗样式：底部居中、圆角、约 96% 屏宽、最高 78% 屏高、
可滑动分类详情、半透明背景和独立关闭按钮；覆盖当前页面但
不触发红果 Activity 的 `onPause`、不重建视频播放器。
普通原生设置入口和通知栏快捷设置也复用同一弹窗。

## 兼容性与生效机制

- 所有开关继续使用 `ModuleSettingsStore` 现有键名。
- `mine_hide_*` 的九个精简选项仍默认启用隐藏，并按原逻辑通知
  `MinePageCleaner` 刷新，不会更改当前账号内容。
- 模块开关、画质、小窗和媒体播放等特殊设置保留原先的即时
  副作用；原生下载进程配置可能仍需要强制停止红果才能更新。
- 不更改 `TTVideoEngine`、小窗 Surface 或后台 MediaSession
  的任何底层播放器结构。

## 回归测试

1. 在首页视频和全集视频的长按原生菜单中点击「Xhongguo 设置」；
   应直接显示当前红果 App 内的设置弹窗，不出现模块主页。
2. 从弹窗首页进入「播放与小窗」，修改一个开关，点击返回：
   应回到分类首页，再关闭弹窗，视频位置和页面不应改变。
3. 从独立 Xhongguo App 打开设置，确认出现同样分类和相同
   开关状态，系统返回在分类内返回分类首页。
4. 修改默认倍速及下载上限，确认编辑器与保存行为与重构前相同。
5. 确认「我的页面」九个开关各自生效，未因 UI 分组改变键名。
6. 测试红果系统设置入口和通知栏面板仍可打开原地设置。
7. 在红果内弹窗中查看日志 `模块设置：已在红果内打开分类弹窗`。

注意：源码编译成功只证明集成可构建；菜单注入和视频页面
连续性仍需真机测试。
